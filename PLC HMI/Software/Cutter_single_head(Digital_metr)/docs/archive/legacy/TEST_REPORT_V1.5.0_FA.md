## بخش ۴ — جدید در V.1.5.0 ⭐

### 4.1 لیست برش ۴۰تایی (۴ صفحهٔ ۱۰تایی)
- دکمه‌های **◀ ▶** و شمارندهٔ «1/4» بالای صفحهٔ لیست (runtime — کنار دکمهٔ خانه).
- «+» تعداد ردیف فعال را تا ۴۰ زیاد می‌کند؛ ردیف‌های هر صفحه بر اساس آن نمایش داده می‌شوند.
- **تست:** ورود عدد در صفحهٔ ۲و۳و۴، جابه‌جایی صفحه وسط ادیت (باید ادیت کنسل شود)، انتخاب ردیف از صفحهٔ ۳ → صفحهٔ اصلی با همان مقدار، ذخیره/بازیابی بعد از خاموش‌روشن، وب‌پورتال هر ۴۰ ردیف.

### 4.2 نامپد لمسی (ورود عدد بدون کیبورد USB)
- صفحهٔ لیست: لمس متراژ/تعداد → نامپد سمت راست باز می‌شود (0-9، ⌫، ✔، ×).
- صفحهٔ اصلی: **لمس خود عدد setpoint** → نامپد؛ ✔ = مثل Enter (حرکت).
- بعد از ✔ متراژ، خودکار وارد ادیت «تعداد» همان ردیف می‌شود (نامپد باز می‌ماند).
- × = انصراف و برگرداندن مقدار قبلی.
- **تست:** هر سه مسیر + هم‌زمانی با کیبورد USB (هر دو باید کار کنند).

### 4.3 پیام خطای محدوده (توست)
- عدد خارج از بازهٔ [طول اولیه .. حداکثر طول] → توست پایین صفحه: «عدد خارج از محدوده مجاز است: X تا Y» + بوق، سپس clamp.
- در هر دو مسیر کیبورد و نامپد، صفحهٔ اصلی و لیست.
- **تست:** عدد کوچکتر از طول اولیه و بزرگتر از حداکثر در هر دو صفحه.

### 4.4 بهینه‌سازی برش (Cutting Stock — الگوریتم FFD) ⭐⭐
- تنظیمات از وب‌پورتال: **طول شاخه** (پیش‌فرض 6000) و **پرت تیغه/kerf** (پیش‌فرض 3mm).
- دکمهٔ نارنجی **«بهینه برش»** بالای صفحهٔ لیست: همهٔ ردیف‌های فعال (متراژ×تعداد) را با First-Fit-Decreasing داخل شاخه‌ها می‌چیند (هر برش kerf مصرف می‌کند).
- پنل نتیجه: تعداد شاخه، پرت کل، لیست شاخه‌به‌شاخه با قطعات و پرت هر شاخه، شاخهٔ جاری هایلایت.
- اجرا: **«حرکت به قطعه»** → محور به طول قطعهٔ جاری می‌رود → برش دومرحله‌ای عادی → با تأیید برش، صف جلو می‌رود و تعداد ردیف مبدأ کم می‌شود → دوباره «حرکت به قطعه». «رد کردن» = پرش از قطعه. «خروج» = بستن.
- پایان صف → توست «بهینه‌سازی تمام شد» + بوق.
- خطاها: ردیف بلندتر از شاخه → پیام با شمارهٔ ردیف؛ لیست خالی → پیام؛ سقف ۲۴۰ قطعه/۶۰ شاخه.
- **تست پیشنهادی:** شاخه 6000، kerf 5، لیست: 2500×2 + 1800×3 + 900×4 → انتظار: ~3 شاخه؛ صحت چینش و پرت را دستی چک کنید؛ یک قطعه را رد کنید؛ وسط کار خروج و ورود دوباره.
- **ایمنی:** «حرکت به قطعه» فقط وقتی referenced و موتور ساکن؛ برش همچنان فقط با دو دست + محافظ.

### 4.5 اسپلش بوت + سلف‌تست
- روشن‌شدن → صفحهٔ سرمه‌ای: METR & CUTTER + نام فارسی + نسخه/LVGL/تاریخ بیلد + خط `Touch/PSRAM/NVS/Heap`.
- همه OK → 2.5s؛ خطا → قرمز + پیام فارسی + بوق + 6s. (RTC روی برد نیست — چک نمی‌شود.)
- **تست:** بوت عادی؛ برای تست FAIL می‌توانید کابل تاچ را جدا کنید (Touch:FAIL باید بیاید).

### 4.6 ایمپورت سایز از سریال (CP2102 روی UART0) — سناریو بند 9 فایل SCENARIO_FA.md
- ترمینال سریال (PuTTY/Termite) روی پورت CP2102، baud **115200** → ارسال `2500X10,1800X5`
- روی HMI دیالوگ «Serial Size List: n rows» + بوق → IMPORT = جایگزینی ردیف‌های 1..n + توست؛ NO = رد.
- پاسخ سریال: `OK: n pairs` / `IMPORTED` / `CANCELLED` / `ERR`.
- **توجه:** CP2102 فلش USB را مستقیم نمی‌خواند (پل UART است) — برای فلش مستقیم ماژول CH376 لازم است؛ پروتکل همین است.
- **تست:** فرمت درست، فرمت خراب (باید ERR)، حین باز بودن دیالوگ دادهٔ جدید (باید نادیده گرفته شود).

### 4.7 وب‌پورتال — باز شدن خودکار + ایمپورت فایل
- بعد از اتصال گوشی به AP، صفحه باید **خودکار** باز شود (captive DNS). اگر نشد: `192.168.4.1`.
- «Import sizes from file»: فایل .txt (`2500X10` هر خط) یا .csv (`2500,10`) → Load file → فرم‌ها پر + rows تنظیم → Save.
- اکسل: Save As CSV سپس همان مسیر.
- **تست:** هر دو فرمت، فایل خراب (پیام No valid rows)، بیش از 40 ردیف (فقط 40 تای اول).

### 4.8 تکمیلی‌های آخر
- **تنظیم شاخه/پرت روی خود پنل بهینه‌سازی:** دکمه‌های [−]/[+] بالای پنل؛ هر تغییر = ذخیره + بازچینی فوری (بند 5.7 سناریو).
- **دکمهٔ سطل قرمز در هدر لیست:** صفرکردن تعداد همهٔ ردیف‌ها با دیالوگ تأیید (بند 4.6).
- **سرعت جوگ مستقل:** فیلد «Jog speed %» در وب — پیش‌فرض همان سرعت برش قبلی؛ تست: جوگ با سرعت متفاوت از حرکت اتومات.
- **پیش‌برش سر شاخه (trim):** ردیف سوم [−]/[+] روی پنل بهینه‌سازی + فیلد وب — طول مفید = شاخه − پیش‌برش (بند 5.8 سناریو). تست: trim=100 → پرت هر شاخه باید 100 بیشتر گزارش شود / قطعات کمتر جا شوند.
- **لیبل پرینت بهینه‌سازی:** هر تأیید برش در این مود → چاپ «2500 B3» (بند 5.9). تست: بیرون بهینه‌سازی فقط طول چاپ شود.
- **قضاوت فنی — اضافه نشد:** «رفرنس خودکار بعد از روشن‌شدن» (حرکت بدون فرمان اپراتور در بوت = ناایمن؛ استاندارد صنعتی: اپراتور شروع می‌کند). «حالت pusher/retract» تایگراستاپ هم به این سخت‌افزار (stop-gauge) مربوط نیست.

### 4.9 سلامت سخت‌افزار (آخرین افزوده)
- **علت ری‌استارت قبلی روی اسپلش** (بند 1.4): تست CRASH با آپلود (SW-Restart)، تست BROWNOUT با افت عمدی تغذیه اگر امن بود.
- **مانیتور دمای تراشه** (بند 1.5): در کار عادی نباید هشدار بدهد؛ برای تست می‌توان آستانه را موقتاً پایین آورد.
- بازبینی پین‌ها انجام شد: GPIO35/36 با PSRAM نوع QSPI بلامانع؛ GPIO3 (start1) پین strapping است ولی بعد از بوت مشکلی ندارد؛ تایمینگ DIR→PUL درایور ≥30µs رعایت می‌شود.

## ⚠️ نکات ریسک برای تست دقیق‌تر (خودارزیابی)
1. **جای دکمه‌های جدید صفحهٔ لیست** — مختصات از روی screens.c محاسبه شده نه چشم؛ اگر با «تعداد» تداخل ظاهری داشت، بگویید تا جابه‌جا کنم.
2. **نامپد روی صفحهٔ اصلی** — ✔ باعث حرکت محور می‌شود؛ حتماً با فاصله از دستگاه تست شود.
3. **مود بهینه‌سازی + مود لیست** — ورود به بهینه‌سازی selected_count را خنثی می‌کند؛ بعد از خروج، انتخاب ردیف عادی را دوباره تست کنید.
4. **حافظه** — ۴۰ ردیف + پنل بهینه‌سازی + وب‌پورتال هم‌زمان: heap را از سریال چک کنید (`Free Heap` هنگام بوت).
5. اولین OTA را با دسترسی USB انجام دهید.
