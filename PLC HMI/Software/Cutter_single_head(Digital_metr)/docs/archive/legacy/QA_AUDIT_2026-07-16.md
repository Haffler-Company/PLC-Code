## Findings

1. Settings help capture is still not correct.
   - `QH1` acknowledges but the soft keyboard remains visible instead of the help modal.
   - Root cause likely: Settings/F1 soft keyboard reopens after navigation and steals the top layer.
   - Required fix: make QA/help opening force-close soft keyboard after settings reinit, or add a normal UI command path that opens help only after the screen is settled.

2. F2 keyboard needs visual polish.
   - Persian labels on the grey left rail are cramped; bottom label can clip.
   - Keyboard shape is usable, but the labels beside the two number boxes need more room or smaller font.

3. F-tab active state needs clearer background.
   - Current active tab is mostly text-color based.
   - User idea is valid: add a subtle active background tint on the right F1-F5 tab button so the current page is obvious.

4. Optimization algorithm is not guaranteed minimum waste.
   - Current algorithm is First-Fit Decreasing.
   - It is fast and safe, but it is a heuristic; it does not mathematically guarantee the lowest possible waste for all lists.
   - Required upgrade: exact bounded optimizer for small/medium piece counts, with fast heuristic fallback for high counts.

5. Optimization high-count behavior is guarded, not frozen.
   - Stress list reached bar capacity and showed a clear error instead of hanging.
   - Next scenario: test near-capacity lists under 500 bars and measure calculation time.

6. Optimization help panel clips at the bottom.
   - `final_opt_help.png` shows the body text is cut near the lower edge.
   - Panel/body height and scroll area need adjustment.

7. Display speed is good in captured idle screens.
   - Overlay commonly showed FPS 60.
   - CPU was generally acceptable on static pages, but CPU can rise during keyboard/help/screen transitions.
   - Continue checking pages that show CPU above ~60 percent after settling.

8. Serial SHOT can still timeout occasionally after navigation/reboot.
   - The final clean `QSTA` log no longer had I2C flood, but long multi-command capture chains still sometimes timed out.
   - Required fix: make `tools/qa_hmi.py` retry SHOT once after timeout and split long capture batches by screen.
