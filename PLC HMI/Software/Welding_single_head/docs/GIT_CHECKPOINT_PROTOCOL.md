# پروتکل نقاط بازگشت ایمن، بکاپ چرخشی و اصلاح رو به جلو (Git Checkpoint & Rolling Backup Protocol)

این مستند، راهنمای حیاتی و قانون قطعی برای جلوگیری از «از دست رفتن کدهای روزهای قبل»، مدیریت بکاپ‌های چرخشی ۱۰ نسخه‌ای و اجرای اصلاح رو به جلو (Forward-Fix Rigor) در پروژه HMI جوش تک‌سر است.

---

## ۱. قانون اساسی: ممنوعیت مطلق بازگشت کورکورانه به عقب (Forward-Fix Only)

> [!CAUTION]
> **قانون قطعی و بدون استثنا:**
> اگر هر برنامه‌نویس یا ایجنتی در حین توسعه دچار اشتباه شد یا باگی به وجود آمد، **به هیچ عنوان حق ندارد برنامه را به نسخه قبل یا چند روز پیش برگرداند (`git reset --hard`، ریورت‌های فله‌ای یا بازنویسی کورکورانه فایل‌ها ممنوع است).**
> 
> **وظیفه توسعه‌دهنده/ایجنت:**
> 1. **ردگیری و پیگیری دقیق (Root Cause Analysis):** بررسی لاگ‌ها، پیدا کردن خط دقیق و تحلیل علت ریشه‌ای خطا.
> 2. **اصلاح جراحی رو به جلو (Fix-Forward):** اصلاح مستقیم و بدون حدس و گمان همان خط یا بلوک مشکل‌دار، بدون آسیب زدن به کارهای قبلی.
> 3. **حفظ کامل دستاوردهای اخیر:** هیچ قابلیتی که در روزهای گذشته اضافه شده نباید به بهانه رفع یک مشکل موضعی پاک یا ریورت شود.

---

## ۲. سیستم بکاپ چرخشی ۱۰ نسخه‌ای (Rolling 10-Backup Architecture)

برای تضمین حداکثر امنیت و در عین حال **جلوگیری از پر شدن حافظه و دیسک**، سیستم بکاپ‌گیری خودکار با ظرفیت ۱۰ نسخه در پوشه `.backups/` پیاده‌سازی شده است:

### اصول سیستم بکاپ چرخشی:
1. **بکاپ‌گیری قبل از هر اقدام اصلاحی:** پیش از هر تغییر، کامیت یا ریفکتور، یک اسنپ‌شات فشرده `.zip` از کلیه فایل‌های سورس و مستندات ساخته می‌شود.
2. **چرخش خودکار ۱۰ نسخه (Rolling FIFO Retention):** سیستم همواره دقیقاً **۱۰ بکاپ اخیر** را نگهداری می‌کند و با ثبت هر بکاپ جدید، قدیمی‌ترین بکاپ‌ها را به صورت خودکار حذف می‌کند تا فضای دیسک اشغال نشود.
3. **عدم آلودگی گیت:** مسیر `.backups/` در `.gitignore` ثبت شده و ریپازیتوری را سنگین نمی‌کند.

### دستورات سریع ابزار بکاپ:
```powershell
# ۱. ایجاد بکاپ جدید قبل از اقدام اصلاحی (همراه با پاکسازی خودکار نسخه‌های قدیمی‌تر از ۱۰)
python tools/backup_manager.py create "fix_heater_interlock"
# یا در پاورشل:
.\tools\backup_manager.ps1 create "fix_heater_interlock"

# ۲. مشاهده لیست ۱۰ بکاپ فعال و حجم اشغال‌شده
python tools/backup_manager.py list

# ۳. استخراج جراحی یک فایل خاص از درون بکاپ بدون بازنویسی کل پروژه
python tools/backup_manager.py restore 1 "src/screens.c"
```

## ۳. انضباط کامیت‌های خرد در Git (میکروکامیت‌های ۱۰ تا ۲۰ دقیقه‌ای)

یکی از دلایل بازگشت‌های مخرب در گذشته، کامیت‌های دیرهنگام (هر ۲ یا ۳ روز یک بار) بود. برای حل ریشه‌ای این مسئله:

> [!IMPORTANT]
> **قانون میکروکامیت (Micro-Commits):**
> هر اقدام اصلاحی، رفع باگ، تنظیم ویجت یا تغییر منطقی باید در فواصل زمانی کوتاه (**هر ۱۰ الی ۲۰ دقیقه یا به ازای هر اصلاح مستقل**) با یک کامیت واضح در Git ثبت شود.
> 
> بدین ترتیب اگر مشکلی پیش بیاید، به جای بازگشت به ۲ یا ۳ روز پیش، می‌توان وضعیت **۱۰ یا ۲۰ دقیقه قبل** را بررسی، مقایسه یا به صورت جراحی بازیابی کرد.

### دستور میکروکامیت خودکار (بکاپ + کامیت گیت همزمان):
```powershell
python tools/backup_manager.py commit "FIX: correct pedal lockout debounce on admin screen"
```
این دستور به صورت خودکار:
1. اسنپ‌شات ZIP جدید تهیه و چرخش ۱۰ نسخه را اعمال می‌کند.
2. فایل‌های سورس اصلاح‌شده را در Git استیج می‌کند (`git add`).
3. کامیت را با پیام استاندارد ثبت می‌کند.

## ۴. استاندارد نام‌گذاری پیام‌های Commit

```
[نوع]: [توضیح کوتاه دقیق به زبان انگلیسی یا فارسی حداکثر در ۱۳ کلمه]

انواع مجاز: CHECKPOINT | FIX | FEAT | UI | REFACTOR | DOCS | HOTFIX
```
**نمونه‌ها:**
- `CHECKPOINT: before tuning bottom bar lamp socket rendering`
- `FIX: immediate emergency cutoff on active edge in tasks.h`
- `UI: lift admin password placeholder 4px for centered baseline`
- `FEAT: add universal 2.4GHz modem WiFi policy IR 1..13`

## ۵. راهنمای بازیابی و مقایسه جراحی (Surgical Inspection Playbook)

هنگامی که خطایی رخ داد، به جای بازگردانی فله‌ای:

### روش ۱: استخراج جراحی از بکاپ‌های ۱۰ نسخه اخیر
```powershell
# استخراج نسخه فایل از بکاپ شماره ۱ به یک فایل پیش‌نمایش (*.restored_preview)
python tools/backup_manager.py restore 1 "src/screens.c"

# مقایسه خط به خط با فایل جاری و جایگزینی دقیق فقط تابع هدف با replace_file_content
```

### روش ۲: مقایسه با کامیت‌های ۲۰ دقیقه قبل در Git
```powershell
# ۱. مشاهده تاریخچه کامیت‌های اخیر
git log -n 5 --oneline -- src/screens.c

# ۲. مشاهده تفاوت دقیق (Diff)
git diff HEAD~1 src/screens.c

# ۳. استخراج کد سالم تابع از کامیت قبلی بدون ریورت کل فایل
git show HEAD~1:src/screens.c | Select-String -Pattern "void draw_temp_gauge" -Context 5,30
```

## ۶. چک‌لیست نهایی قبل از تحویل (Zero-Guesswork Audit Gate)

قبل از اعلام پایان هر اقدام اصلاحی:

1. **بررسی عدم وجود تغییرات ناخواسته (`git diff`):**
   ```powershell
   git diff HEAD --stat
   ```
2. **اعتبارسنجی بیلد فریم‌ور:**
   ```powershell
   & "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run
   ```
3. **ثبت وضعیت در `docs/WORKLOG.md`:** ثبت دقیق اقدام اصلاحی و شماره بیلد.
