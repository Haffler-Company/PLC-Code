# سند جامع معماری کنترل و مانیتورینگ ابری ماشین‌آلات هافلر
## نظام‌نامه تله‌متری اینترنت اشیا (IIoT)، پروتکل MQTT، ارتباط سریال و استانداردهای اسکادا (SCADA)
**نسخه سند:** ۱.۰.۰ | **تاریخ تصویب:** ۲۰۲۶.۰۹.۱۷ | **مرجع:** مهندسی اتوماسیون هافلر (Haffler Industrial Automation)

---

## ۱. هدف و چشم‌انداز معماری
این سند چارچوب قطعی ارتباطی، تله‌متری بلادرنگ و امنیت سایبری صنعتی را برای اتصال کلیه ماشین‌آلات هافلر به پرتال وب و سرور ابری تعریف می‌کند. تمامی ایجنت‌های توسعه فریمورک (ESP32-S3 / STM32 / FreeRTOS) و طراحان سیستم‌های مانیتورینگ ملزم به رعایت بی‌کم‌وکاست این مشخصات هستند.

---

## ۲. قانون حیاتی اتصال واقعی (Real Connection Enforcement)

> **قانون قطعی و بدون استثنا:**
> نمایش داده‌های زنده و صدور فرامین کنترلی به تجهیزات صنعتی **تنها و تنها در صورت برقراری اتصال سخت‌افزاری واقعی (پورت سریال COM) یا اتصال شبکه برخط اینترنتی (پروتکل ابری MQTT)** مجاز است.

1. **حالت آفلاین (OFFLINE State):**
   - در صورت عدم دریافت تله‌متری در بازه زمانی ۶۰ ثانیه‌ای یا قطع کابل سریال، وضعیت دستگاه فوراً به `OFFLINE` تغییر می‌یابد.
   - **ممنوعیت داده‌های جعلی (No Mock Data):** سیستم به هیچ عنوان داده‌های فرضی، نوسانات شبیه‌سازی‌شده یا مقادیر تخمینی تولید نمی‌کند.
   - **بلاک کامل فرامین حرکتی و حرارتی:** فرامین اجرایی نظیر شروع فرآیند انجماد، استارت چرخه جوشکاری، برش، پانچ و غیره مسدود شده و پیام صریح زیر صادر می‌گردد:
     > «دستگاه به اینترنت یا سرور ابری متصل نیست. کنترل و مانیتورینگ فقط در صورت برقراری اتصال فعال مجاز است.»
2. **حالت آنلاین (ONLINE State):**
   - مقادیر سنسورها به صورت کاملاً زنده بازتاب داده می‌شوند و تغییر مقادیر رسپی و فرامین اجرایی با ثبت در لاگ ممیزی انجام می‌گیرد.

## ۳. استاندارد پروتکل ابری MQTT (Internet of Things)

### ۳.۱ ساختار نام‌گذاری تاپیک‌ها (Topic Hierarchy)
الگوی استاندارد تاپیک‌های هافلر به فرمت زیر تعریف شده است:
`haffler/{machine_slug}/{device_id}/{channel}`

| ماشین | Machine Slug | Device ID پیش‌فرض |
|:---|:---|:---:|
| دستگاه بستنی‌ساز صنعتی | `ice_cream` | `ICE-01` |
| جوشکاری تک‌سر UPVC | `weld_single` | `WELD-01` |
| جوشکاری دوسر UPVC | `weld_double` | `WELD-02` |
| اره برش دیجیتال تک‌سر | `cut_single` | `CUT-01` |
| اره برش دیجیتال دوسر | `cut_double` | `CUT-02` |
| تمیزکن گوشه CNC چهار محور | `corner_clean` | `CNC-01` |
| پرس پانچ هیدرولیک آلومینیوم | `punch` | `PUNCH-01` |
| فرز کپی و سه‌سوراخ‌زن | `copy_router` | `ROUTER-01` |
| تزریق گاز آرگون شیشه دوجداره | `gas_filling` | `GAS-01` |
| ماشین‌آلات نانوایی و میکسر | `bakery` | `BAKE-01` |

---

### ۳.۲ کانال‌های تاپیک (Topic Channels)

#### الف) کانال وضعیت برخط و LWT (`/online`):
- **تاپیک:** `haffler/{machine_slug}/{device_id}/online`
- **پیام برخط شدن (Connect):** `{"status": "online", "fw_ver": "4.4.0", "ts": 1789587200}` (با Retain = true)
- **پیام آخرین وصیت (LWT - Last Will & Testament):** `{"status": "offline", "reason": "unexpected_disconnect"}`

#### ب) کانال ارسال تله‌متری سنسورها (`/telemetry`):
- **تاپیک:** `haffler/{machine_slug}/{device_id}/telemetry`
- **فرکانس ارسال:** ۱ ثانیه در حین کار فرآیند، ۵ ثانیه در حالت آماده‌باش.
- **نمونه پکت دستگاه بستنی‌ساز:**
```json
{
  "device_id": "ICE-01",
  "mode": "freezing",
  "hopper_temp": 4.1,
  "cylinder_temp": -7.6,
  "viscosity_pct": 82,
  "motor_current_a": 7.2,
  "compressor_q1": true,
  "air_pump": true,
  "dispense_head": false,
  "alarms": [],
  "timestamp": 1789587200
}
```

#### ج) کانال صدور فرمان کنترلی (`/cmd`):
- **تاپیک:** `haffler/{machine_slug}/{device_id}/cmd`
- **نمونه ساختار فرمان:**
```json
{
  "req_id": "req_1789587210",
  "action": "start_freezing",
  "params": {
    "target_viscosity": 85,
    "target_cyl_temp": -8.0
  },
  "issuer": "admin",
  "timestamp": 1789587210
}
```

#### د) کانال بازخورد و تاییدیه سخت‌افزار (`/ack`):
- **تاپیک:** `haffler/{machine_slug}/{device_id}/ack`
```json
{
  "req_id": "req_1789587210",
  "status": "SUCCESS",
  "executed_action": "start_freezing",
  "code": 0,
  "message": "کمپرسور برودتی با تاخیر ضد شوک ۱۸۰ ثانیه‌ای استارت شد."
}
```

## ۴. استاندارد ارتباط سریال صنعتی (UART / RS485 Bridge)

برای ارتباط مستقیم از طریق کابل USB/RS485 به پرتال وب (سرور محلی Haffler Web روی COM8):
- **باودریت استاندارد:** ۹۲۱,۶۰۰ یا ۱۱۵,۲۰۰ با تنظیمات `8-N-1`
- **ساختار فریم‌های باینری / اسکی:**
  - ارسال از سرور به برد: `$CMD:ACTION,PAYLOAD*CRC\n`
  - نمونه: `$EVENT:KEY:START*4A\n` یا `$NAV:SETUP*1B\n`
  - ارسال تله‌متری از برد به سرور:
    `$TEL:HOP=4.1,CYL=-7.6,CUR=7.2,VIS=82,Q1=1*5F\n`

## ۵. الزامات مهندسی در کدهای فریمورک (ESP32-S3 & FreeRTOS)

1. **تفکیک تسک‌های کنترلی از تسک شبکه:**
   - تسک مانیتورینگ سنسورها و ماشین حالت (FSM) با اولویت `Priority 5` روی هسته ۱ (Core 1) اجرا گردد.
   - تسک ارتباطات MQTT و سریال با اولویت `Priority 3` روی هسته ۰ (Core 0) اجرا شود تا تأخیرات شبکه بر ایمنی فرآیند اثر نگذارد.
2. **سگ نگهبان سخت‌افزاری (Task Watchdog Timer):**
   - تسک شبکه و تسک ماشین حالت باید مجهز به تغذیه WDT در حلقه‌های اصلی باشند.
3. **ذخیره‌سازی غیرفرار پارامترها (NVS):**
   - تمامی پارامترها و فرمول‌های دریافتی از سرور باید اعتبارسنجی شده (اعتبارسنجی بازه حداقل و حداکثر) و سپس در حافظه دائمی NVS ذخیره شوند.
