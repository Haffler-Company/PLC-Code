## اصول پایه (از اپل → HMI ما)

| اصل اپل | معنی برای ما |
|---------|----------------|
| **Clarity** | متن خوانا، عدد درشت، یک عمل اصلی در هر ناحیه، بدون شلوغی |
| **Deference** | UI پشت محتوا می‌ایستد؛ عدد/لیست قهرمان صفحه است نه دکوراسیون |
| **Depth** | لایه‌ها با سایهٔ نرم و کنتراست جدا می‌شوند؛ نه گرادیان بنفش و نه سایهٔ چندلایهٔ اغراق‌شده |

## رنگ (پالت پیشنهادی صنعتی + حس iOS)

| نقش | هگز پیشنهادی | کاربرد |
|-----|--------------|--------|
| Primary | `#007AFF` / `#0A84FF` | خانه، صفحه، لینک عمل |
| Success | `#34C759` / `#1C9B67` | تأیید، OK، پرینتر OK |
| Warning | `#FF9500` / `#EF6C00` | بهینه، هشدار غیر بحرانی |
| Danger | `#FF3B30` / `#B90000` | سطل، استاپ، حذف |
| Label | `#1C1C1E` | متن اصلی |
| Secondary label | `#8E8E93` | واحد `mm`، راهنما |
| Fill / card | `#FFFFFF` | کارت، دیسک موقعیت، عنوان |
| Grouped bg | `#F2F2F7` / `#C0C0C0` فعلی دستگاه | پس‌زمینهٔ صفحه — مهاجرت تدریجی به خاکستری روشن‌تر |
| Separator | `#C6C6C8` | خط/بوردر ۱px |
| Numpad chrome | `#243447` + کلید `#F4F9FC` | مثل F1 طراح |

قوانین:
- یک Primary در هر صفحه کافی است.
- قرمز فقط برای خطر/حذف؛ سبز برای تأیید ایمن.
- کنتراست متن روی پس‌زمینه را حفظ کن (عدد قرمز روی سفید OK؛ خاکستری روی خاکستری نه).

## چیدمان و سایز (۴۸۰×۳۲۰)

| قاعده | مقدار |
|-------|--------|
| شبکه | مضارب **۸** (۸ / ۱۶ / ۲۴ / ۳۲ / ۴۰ / ۴۸) |
| حاشیه لبه | ≥ ۸px؛ ترجیح ۱۲–۱۶ برای کارت |
| هدف لمس حداقل | **۴۰×۴۰** px (نزدیک ۴۴pt اپل، مقیاس‌شده) |
| فاصله بین کنترل‌های هدر | ≥ ۴–۸px بدون هم‌پوشانی |
| شعاع گوشه | ۸–۱۲ کارت کوچک؛ ۱۴–۱۶ کارت بزرگ؛ دایره کامل فقط برای دیسک/آیکن گرد |
| یک ترکیب در ویوپورت اول | برند/عنوان + یک محتوای اصلی + گروه CTA — نه داشبورد شلوغ |

سلسله‌مراتب:
1. عدد/لیست (قهرمان)
2. عنوان صفحه
3. کنترل‌های ثانویه (صفحه، ابزار)
4. کروم تزئینی (حداقل)

## سایه و عمق

| سطح | shadow_width | opa | offset | کاربرد |
|-----|--------------|-----|--------|--------|
| Flat | 0 | — | — | دکمهٔ تخت هدر |
| Raised soft | 16–24 | ~30% | y=4..8، x=0..8 | دیسک اصلی، نامپد |
| Card | 8–12 | ~20% | y=2..4 | کارت تنظیمات |

- سایهٔ رنگی آبی تیرهٔ غلیظ ممنوع مگر برای دیسک خاص تأییدشده.
- بدون glow بنفش / چندلایهٔ فانتزی.

## آیکن و تایپ

| نوع | فونت / منبع |
|-----|-------------|
| عدد ماشین | `ui_font_digit*` |
| فارسی عنوان | `ui_font_titr*` / `ui_font_naz*` |
| UI لاتین/نماد | Montserrat ۱۴–۲۴ |
| نماد سیستم | `LV_SYMBOL_*` یا تصاویر EEZ (`img_*`) |

- آیکن + برچسب کوتاه وقتی جا هست (مثل F1 طراح).
- نماد تنها وقتی هدف لمس ≥ ۴۰px و معنی واضح است.
- فونت naz subset است — قبل از متن جدید کاراکتر را چک کن.

## UX تعاملی (سازگار با اپل + ایمنی ماشین)

- لمس → فلگ → کار سنگین در Task2 (هرگز `loadScreen`/NVS در callback).
- بازخورد فوری: بوق کوتاه / تغییر رنگ pressed (translate ۲px کافی است).
- یک مسیر خروج واضح از دیالوگ؛ همیشه `GUI.lock_screen = false` در همهٔ close pathها.
- حالت خطر (E-STOP) باید از بقیهٔ UI متمایز و غیرقابل اشتباه باشد.
- در حالت برش، جوگ/منوهای خطرناک قفل بمانند.

## مسیر شبیه‌ساز → فریمور (ایده برای طراحی خودت)

1. **ایده را در شبیه‌ساز بکش**  
   - F1: `simulator/settings-f1-designer.html` + `tools/designer_f1_shot.py`  
   - لیست منطق: `tools/list_ui_sim.py`  
   - هدف آینده: طراح HTML جدا برای Main و List (مثل F1) در `simulator/`
2. **SHOT مرجع طراح** را ذخیره کن (`simulator/shots/designer_*.png` یا `user_*_target.png`).
3. **پورت به `ui_extras.h`** (نه rewrite کامل `screens.c` مگر ضروری).
4. **آپلود + SCR + SHOT برد** → `board_*.png`.
5. **حلقهٔ قاضی‌ها** (۳–۵ دور) تا ضعف بحرانی صفر شود — فقط آن‌وقت «تمام».

ایده‌های طراحی در شبیه‌ساز:
- یک فایل HTML ۴۸۰×۳۲۰ برای Main (دیسک + هدر) و یکی برای List.
- کنترل درگ مثل F1 برای مختصات اولیه، بعد قفل به مضارب ۸.
- دکمهٔ «Export coords» برای چسباندن به `f1_layout_check` / چک‌لیست.
- حالت «Compare»: طراح و `board_*.png` را نیمه‌شفاف روی هم.
