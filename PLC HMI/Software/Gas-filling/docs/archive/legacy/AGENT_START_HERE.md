# Agent Start Here

This is the first file a future agent should read in the Gas Filling project.

The project is an ESP32-S3 HMI for an argon gas filling machine with a real 480x320 ST7796 LCD, capacitive touch, LVGL 9, two valve outputs, and a buzzer. Work must be verified on the real display using the serial agent when possible.

## Golden Rules

1. Treat the real LCD as the source of truth. Compile success alone is not enough for UI/display work.
2. Use `ST7796_DRIVER` for this display. `ILI9341_DRIVER` was wrong.
3. Keep `tft.setSwapBytes(true)` and `tft.pushColors(..., true)` unless a real hardware screenshot proves a better setting.
4. Keep LVGL 9 image data in the correct `RGB565A8` layout: RGB565 plane first, alpha plane second.
5. Do not pulse physical valve outputs without explicit user approval.
6. Send `SAFE` after hardware-facing tests.
7. Do not copy logic blindly from the cutter or welding projects. Use them as references for hardware patterns, screenshots, and HMI quality.
8. After every upload, append new facts to `docs/GAS_FILLING_TECHNICAL_KNOWLEDGE.md` via `-Knowledge` (or `-Knowledge none`).
9. Prefer `.\scripts\program.ps1 -Port COM3 -Knowledge "..."` over raw arduino-cli.
10. Never wipe `artifacts/build-cache/core` casually. Use `-Force` / `-CleanSketch` (sketch only). Use `-Clean` only if the cache is corrupt.

## Known-Good Agent Commands

```powershell
.\scripts\doctor.ps1
.\scripts\program.ps1 -Port COM3 -Knowledge "short fact"
.\scripts\program.ps1 -Port COM3 -Force -Knowledge "forced sketch rebuild"
.\scripts\upload.ps1 -Port COM3 -SkipBuild -Knowledge none
.\scripts\upload.ps1 -Port COM3 -SkipBuild -FullFlash -Knowledge "full flash repair"

python .\tools\hmi_agent.py --port COM3 ready
python .\tools\hmi_agent.py --port COM3 cmd PING
python .\tools\hmi_agent.py --port COM3 cmd STAT
python .\tools\hmi_agent.py --port COM3 shot --out .\artifacts\shots\check.png
python .\tools\hmi_agent.py --port COM3 smoke
```

Upload now auto-verifies with `PING`. If arduino "fast reflash" corrupts the image (silent boot / no PING), scripts fall back to a complete esptool write (`-FullFlash`). Never assert RTS on USB-JTAG — it drops the chip into DOWNLOAD mode.

`smoke` navigates and captures screenshots only. It does not activate the valves.

## Build Notes

Use the project scripts (not raw `arduino-cli`) so incremental cache, upload retries, and knowledge logging stay consistent.

Proven FQBN options:

- `FlashSize=16M`
- `PartitionScheme=huge_app`
- `PSRAM=enabled`
- `USBMode=hwcdc`
- `UploadSpeed=921600`

Speed rules:

- Fixed `--build-path artifacts/build-cache` + `--jobs 0`.
- Upload uses `--input-dir` (never recompiles during flash).
- `-Force` / `-CleanSketch` clears sketch objects only and **keeps** `core/` + `libraries/`.
- `-Clean` wipes the whole cache (cold rebuild — minutes). Avoid.
- Scripts auto-retry sketch rebuild once on compile failure, and USB upload up to 3 times.
- Close serial monitors / `hmi_agent` before flash so COM is free.

Full screenshot capture requires working PSRAM. On the tested board, `PSRAM=opi` compiled but runtime PSRAM was zero; `PSRAM=enabled` worked.
