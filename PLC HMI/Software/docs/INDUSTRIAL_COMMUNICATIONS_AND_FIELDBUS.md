# راهنمای جامع پروتکل‌های مخابرات صنعتی و فیلدباس (Industrial Communications & Fieldbus)
## پیاده‌سازی پروتکل‌های Modbus RTU / TCP، ارتباط سریال RS485 و تله‌متری وب‌سوکت

> **هدف:** اتصال استاندارد کنترلرهای HMI هافلر به اتوماسیون بالادست (PLCهای کارخانه، اسکادا SCADA، نرم‌افزارهای مدیریت کارگاه و شبکه داخلی) با قابلیت اطمینان ۱۰۰٪، بدون از دست رفتن پکت‌ها و بدون تداخل با چرخه‌های حرکتی ماشین.

## ۱. پروتکل استاندارد صنعتی Modbus RTU بر بستر RS485

کنترلرهای هافلر می‌توانند در نقش Modbus Slave (پاسخ به خطوط اسکادا) یا Modbus Master (فرمان به اینورترهای VFD و درایورهای سروو) عمل کنند.

### ۱.۱. زمان‌بندی دقیق انتهای فریم (3.5 Character Silent Interval)
طبق استاندارد مالبوس، تشخیص انتهای یک پکت از طریق سکوت خط به مدت ۳.۵ کاراکتر انجام می‌شود:
$$\text{Silent Interval} = \frac{3.5 \times 10 \text{ bits}}{\text{Baud Rate}}$$

* در بادریت **9600 bps**: زمان سکوت برابر **۳.۶۵ میلی‌ثانیه**.
* در بادریت **115200 bps**: زمان سکوت برابر **۱.۷۵ میلی‌ثانیه** (حداقل مجاز در استاندارد).

### ۱.۲. محاسبه استاندارد خطای فریم (CRC-16 Modbus)
```c
uint16_t modbus_crc16(const uint8_t *buffer, uint16_t len) {
    uint16_t crc = 0xFFFF;
    for (uint16_t pos = 0; pos < len; pos++) {
        crc ^= (uint16_t)buffer[pos];
        for (int i = 8; i != 0; i--) {
            if ((crc & 0x0001) != 0) {
                crc >>= 1;
                crc ^= 0xA001;
            } else {
                crc >>= 1;
            }
        }
    }
    return crc;
}
```

## ۲. کنترل پین جهت فرستنده/گیرنده درایور RS485 (DE / RE Pin Control)

تراشه‌های درایور RS485 (مانند MAX485 یا SP3485) برای ارسال نیازمند فعال‌سازی پین `DE` (Driver Enable) و غیرفعال‌سازی `RE` (Receiver Enable) هستند.

> **خطای رایج کارگاهی (Clipping Bug):**  
> اگر به محض اتمام حلقه ارسال بایت‌ها، پین DE را `LOW` کنید، آخرین بایت یا بیت استاپ در شیفت رجیستر UART باقی مانده و نصفه ارسال می‌شود!

```c
// ✅ الگوی استاندارد و بی‌نقص کنترل جهت RS485 در ESP32:
void rs485_send_packet(uart_port_t uart_num, gpio_num_t de_pin, const uint8_t* data, size_t len) {
    // ۱. روشن کردن فرستنده
    gpio_set_level(de_pin, 1);
    esp_rom_delay_us(10); // پایداری سیگنال

    // ۲. نوشتن داده در UART
    uart_write_bytes(uart_num, (const char*)data, len);

    // ۳. انتظار قطعی برای خالی شدن کامل رجیستر انتقال سخت‌افزاری (نه فقط بافر FIFO):
    ESP_ERROR_CHECK(uart_wait_tx_done(uart_num, pdMS_TO_TICKS(100)));

    // ۴. بازگشت به حالت شنود خط (Receiver Mode)
    gpio_set_level(de_pin, 0);
}
```

## ۳. نگاشت استاندارد رجیسترهای مالبوس (Modbus Memory Map)

تمامی پارامترهای ماشین در ساختار ۴ جدول استاندارد نگاشت می‌شوند:

| نوع داده مالبوس | محدوده آدرس | دسترسی | کاربرد در ماشین‌های هافلر |
|:---|:---:|:---:|:---|
| **Discrete Inputs** (1x) | 10001 - 10032 | فقط خواندنی | وضعیت میکروسوئیچ‌ها، پدال، E-STOP و سنسورهای القایی |
| **Coils** (0x) | 00001 - 00032 | خواندن/نوشتن | وضعیت بوبین رله‌ها (شیرها، موتور اسپیندل، المنت‌ها) |
| **Input Registers** (3x) | 30001 - 30020 | فقط خواندنی | دمای لحظه‌ای MAX6675، موقعیت پالس انکودر، فشار سنسور آرگون |
| **Holding Registers** (4x)| 40001 - 40050 | خواندن/نوشتن | طول برش هدف، دمای ست‌پوینت، زمان ذوب جوش، ضریب کالیبراسیون |

## ۴. تله‌متری وب‌سوکت و پورتال کارگاهی (WebSocket Telemetry Protocol)

جهت نمایش زنده وضعیت دستگاه روی کامپیوتر یا تبلت کارگاه از طریق شبکه وای‌فای، یک پکت متنی کم‌حجم با فرمت JSON هر ۲۵۰ میلی‌ثانیه بر بستر WebSocket مخابره می‌شود:

```json
{
  "machine_id": "CUTTER-SINGLE-01",
  "fw_version": "V.1.8.2",
  "state": "EXECUTE",
  "target_len_mm": 1250.5,
  "actual_pos_mm": 1250.4,
  "clamped": true,
  "blade_active": true,
  "shift_cuts": 482,
  "alarms": []
}
```

> **قانون ایمنی بیسیم:** فرامین پرخطر (حرکت تیغه یا بستن جک با نیروی بالا) هرگز از طریق وای‌فای یا شبکه بیسیم مجاز نیست و صرفاً باید با شستی‌های سیم‌کشی‌شده فیزیکی محلی (پدال یا دو شستی همزمان) اجرا شوند.
