## HAFFLER CLOUD FLEET IOT & REMOTE TELEMETRY SPECIFICATION (11 MACHINES)

## ۲. ساختار استاندارد تاپیک‌های MQTT (Standardized Topic Namespace)

تمامی دستگاه‌ها بر اساس فرمت استاندارد زیر نام‌گذاری و مسیریابی می‌شوند:

### الف) شناسایی دستگاه و اعلان آنلاین/آفلاین (LWT & Online)
* **تاپیک:** `haffler/<machine_model>/<device_id>/online`
* **پیام LWT (در زمان قطعی ناگهانی):**
  ```json
  {"online": false}
  ```
* **پیام آنلاین شدن برد:**
  ```json
  {
    "online": true,
    "dev_id": "HAFFLER-ICE-93D4E1",
    "model": "ICE CREAM CM-700",
    "ver": "V1.4.2",
    "ip": "192.168.1.108"
  }
  ```

### ب) ارسال متناوب تلمتری و سنسورها (Periodic Telemetry)
* **تاپیک:** `haffler/<machine_model>/<device_id>/telemetry`
* **دوره تناوب:** هر ۱۰ ثانیه در حالت عادی، یا ارسال آنی بلافاصله پس از تغییر وضعیت رله‌ها یا دریافت فرمان.

### ج) دریافت فرامین کنترلی از پورتال (Remote Commands)
* **تاپیک اختصاصی ماشین:** `haffler/<machine_model>/<device_id>/cmd`
* **تاپیک فراگیر دسته ماشین:** `haffler/<machine_model>/broadcast/cmd`
* **تاپیک توقف اضطراری کل کارخانه:** `haffler/all/cmd`

### د) پاسخ اجرای فرمان به پورتال (Command Response)
* **تاپیک:** `haffler/<machine_model>/<device_id>/cmd_resp`
* **فرمت پاسخ:**
  ```json
  {
    "dev_id": "HAFFLER-ICE-93D4E1",
    "ok": true,
    "msg": "Emergency Stop Executed",
    "req_id": "cmd_1726123456"
  }
  ```

## ۳. نگاشت مدل‌های ۱۱ ماشین در سامانه ابری (Machine Model Keys)

|:---:|:---|:---|:---|
| ۱ | `ice_cream` | بستنی‌ساز صنعتی دو کمپرسور CM-700 | دمای T1، دمای T2، شمارنده قیف، وضعیت پارو و شستشو |
| ۲ | `welding_single_head` | جوش تک‌سر پروفیل UPVC | دمای اتو (۲۴۵°C)، فشار باد، زمان ذوب و فشرده‌سازی |
| ۳ | `welding_double_head` | جوش دوسر پروفیل UPVC | دمای سر چپ و راست، زمان‌بندی هم‌زمان، متر دیجیتال |
| ۴ | `cutter_single_head` | اره تک‌سر دیسکی دیجیتال | طول برش خط‌کش انکودر، زاویه ۴۵/۹۰، تعداد برش |
| ۵ | `cutter_double_head` | اره دوسر زاویه‌زن دیجیتال | فاصله هدها، زوایای برش ترکیبی، انکودر طولی |

| ۷ | `copy_router` | کپی‌روتر و سه‌سوراخ‌زن | دوران اسپیندل، فشار باد جک‌های نگه‌دارنده پروفیل |
| ۸ | `aluminum_punching` | پرس پانچ هیدرولیک آلومینیوم | سنسور فشار روغن هیدرولیک، شمارنده ضربات قالب |
| ۹ | `bakery` | فر دوار و خمیرپز صنعتی | دمای کوره، سرعت چرخش سینی، تایمر پخت |
| ۱۰ | `gas_filling` | تزریق گاز آرگون شیشه دوجداره | سنسور غلظت گاز خروجی، فشار تزریق، حجم گاز |
| ۱۱ | `config_test` | تستر عیب‌یاب و دیاگ کارخانه | ممیزی کلیه ورودی/خروجی‌ها، تست بردهای تولیدی |

## ۴. استانداردهای تاب‌آوری و ضد قطعی شبکه (Reliability & Anti-Filter Rigor)

1. **پورت امن وب‌سوکت برای مرورگر و موبایل (WSS Port 8884 / 8081):**
   - ارتباط وب‌داشبورد با سرور ابری از طریق پروتکل امن WSS با رمزنگاری SSL/TLS انجام می‌شود (HiveMQ روی پورت 8884، Mosquitto روی پورت 8081 و EMQX روی پورت 8084).
2. **چرخش خودکار سرورها (Broker Failover in C Firmware & Web):**
   - کنترلر ESP32 و پورتال تحت وب در صورت قطع ارتباط، بلافاصله بین سرورهای سه‌گانه سوئیچ می‌کنند (`broker.hivemq.com` ↔ `test.mosquitto.org` ↔ `broker.emqx.io`).
3. **ایزولاسیون کامل هسته‌ها (Core 0 vs Core 1):**
   - تسک شبکه ابری (`cloud_worker_task`) منحصراً در **هسته ۰** اجرا می‌شود و اولویت پایین‌تری نسبت به تسک اسکن PLC دارد.
   - هرگز نباید تاخیر شبکه اینترنت یا سوکت TCP باعث کوچک‌ترین افت فریم در نمایشگر LVGL (هسته ۱) یا تاخیر در واکنش به سنسورهای ماشین شود.
4. **حفاظت از رم داخلی (SRAM > 40KB):**
   - بافرهای پکت‌های MQTT حداکثر ۱KB فشرده شده تا هیچ‌گونه افت حافظه رخ ندهد.
