### ماژول ۱: تفکیک دو هسته‌ای FreeRTOS و چرخه اسکن تعینی (Core 0 vs Core 1 Decoupling)

#### صورت چالش:
هنگام اجرای انیمیشن‌های سنگین یا رندر گرافیک روی هسته، اسکن سنسورها، دریافت پالس‌های انکودر یا اینترلاک‌های ایمنی پنیوماتیک دچار تاخیر (Jitter) می‌شوند که می‌تواند موجب خسارت فیزیکی به قالب یا تیغ اره گردد.

#### الگوی استاندارد هافلر:
```c
/* هسته ۱: منحصراً رندرینگ و محاسبات گرافیکی LVGL */
xTaskCreatePinnedToCore(lvgl_render_task, "LVGL_Task", 16384, NULL, 5, NULL, 1);

/* هسته ۰: چرخه کنترل سخت‌افزار (PLC Scan Cycle)، پروتکل‌های مخابراتی، وای‌فای و وب‌سرور */
xTaskCreatePinnedToCore(plc_scan_task, "PLC_Task", 8192, NULL, 10, NULL, 0);
```

#### قوانین طلایی ارتباط بین هسته‌ها:
1. **عدم فراخوانی مستقیم توابع UI از هسته ۰:** هسته ۰ هرگز نباید مستقیماً `lv_label_set_text` یا توابع مشابه را صدا بزند؛ در غیر این صورت کرش `LoadStoreError` یا `Double Exception` رخ می‌دهد.
2. **قفل زمانی مقید بازگشتی:** هرگونه تعامل با LVGL باید درون محدوده قفل با مهلت زمانی مشخص باشد:
   ```c
   if (lvgl_lock(pdMS_TO_TICKS(50))) {
       /* اعمال امن تغییرات در متغیرهای UI */
       lvgl_unlock();
   }
   ```
3. **متغیرهای فرار اتمیک (Volatile Atomics):** متغیرهای اشتراکی بین هسته‌ها (مانند وضعیت امرجنسی استپ یا سنسورها) باید با کلیدواژه `volatile` یا ساختارهای اتمیک تعریف شوند.

### ماژول ۲: سامانه ارتقای دوگانه فریمور (Dual OTA Architecture)

#### صورت چالش:
در برخی کارگاه‌ها اینترنت در دسترس نیست و تکنسین باید با هات‌اسپات موبایل به صورت مستقیم فریمور را ارسال کند. در کارگاه‌های دیگر دستگاه باید بتواند با وای‌فای متصل به اینترنت، آخرین پکیج پایدار را مستقیماً از سرور ابری آروان‌کلاد دانلود و نصب نماید.

#### الگوی استاندارد هافلر:
وب‌اپلیکیشن دستگاه (`#t-ota`) باید دارای دو زیربخش مجزا با سگمنتد کنترل اپل باشد:

1. **ارتقای محلی آفلاین (Local Direct Upload):**
   - آپلود استریمی بدون اشغال حافظه موقت (Chunked Multi-part):
     ```c
     esp_ota_handle_t ota_handle;
     const esp_partition_t *update_partition = esp_ota_get_next_update_partition(NULL);
     esp_ota_begin(update_partition, OTA_WITH_SEQUENTIAL_WRITES, &ota_handle);
     /* حلقه نوشتن چانک‌های ۴ کیلوبایتی */
     esp_ota_write(ota_handle, chunk_buf, chunk_len);
     esp_ota_end(ota_handle);
     esp_ota_set_boot_partition(update_partition);
     ```
2. **ارتقای آنلاین ابری (Cloud Online OTA):**
   - اسکن شبکه‌های وای‌فای موجود بدون افت فریم و بدون نشت رم (`/api/wifi/scan`).
   - اتصال به اکسس‌پوینت کارگاه با ذخیره در NVS (`/api/wifi/connect`).
   - دانلود بایت‌به‌بایت فایل `firmware.bin` از مسیر اختصاصی باکت سرور (مثلاً `https://ota.haffler-infi.ir/upvc/welding-single-head/firmware.bin`).
   - استعلام پیشرفت زنده درصد دانلود و فلش از طریق اندپوینت `/api/ota/status`.
   - پس از اتمام موفق، ارسال سیگنال ریبوت کنترلر.

### ماژول ۴: سیستم آلارم ISA-18.2 و نشانگر قرمز خطاهای جدید (Dynamic Unread Badge)

#### صورت چالش:
اپراتور باید به محض بروز یک خطای جدید در فرآیند صنعتی، متوجه آن شود. اما پس از بررسی صفحه خطاها، کلید نباید همواره قرمز و آزاردهنده باقی بماند تا برای خطای بعدی مجدداً کارایی داشته باشد.

#### الگوی استاندارد هافلر بر پایه دو متغیر ۳۲ بیتی در NVS:
```c
static uint32_t s_fault_total_logged = 0; // شمارنده تجمعی کل خطاهای ماشین
static uint32_t s_fault_last_viewed  = 0; // شماره آخرین خطای مشاهده‌شده توسط کاربر

void fault_log_record(fault_code_t code, int16_t value) {
    /* ثبت در حلقه لاگ NVS */
    s_fault_total_logged++;
    storage_set_u32("flt_tot", s_fault_total_logged);
}

bool fault_log_has_unread(void) {
    if (s_log.count == 0) return false;
    return (s_fault_total_logged > s_fault_last_viewed);
}

void fault_log_mark_read(void) {
    s_fault_last_viewed = s_fault_total_logged;
    storage_set_u32("flt_view", s_fault_last_viewed);
}
```

* **رفتار در UI:**
  - اگر `fault_log_has_unread() == true`: کلید خطاها (`fault_btn`) فوراً قرمز آلرت صنعتی (`#dc2626`) با کادر هایلایت (`#fca5a5`) می‌شود.
  - به محض لمس کلید و باز شدن پنجره خطاها: `fault_log_mark_read()` صدا زده شده و کلید به خاکستری متالیک آرام (`#334155`) برمی‌گردد و تا آمدن خطای بعدی عادی می‌ماند.

### ماژول ۵: تکنیک رندرینگ بدون افت فریم (Dirty-Driven Architecture)

#### صورت چالش:
افت فریم و لرزش انیمیشن‌ها روی ال‌سی‌دی‌های صنعتی موازی ILI9488 یا ST7796.

#### قوانین الزامی:
1. **به‌روزرسانی مشروط به تغییر مقدار (Dirty Check):**
   ```c
   /* نادرست: اجرای بی‌قیدوشرط در هر چرخه تیک */
   lv_label_set_text_fmt(lbl_temp, "%.1f C", cur_temp);

   /* درست و استاندارد زیمنس/اپل: بررسی مقدار قبلی */
   static float s_last_temp = -999.0f;
   if (fabsf(cur_temp - s_last_temp) >= 0.1f) {
       s_last_temp = cur_temp;
       lv_label_set_text_fmt(lbl_temp, "%.1f C", cur_temp);
   }
   ```
2. **سایه نرم‌افزاری اکیداً صفر (`shadow_width = 0`):** هیچ المنتی نباید سایه نرم‌افزاری فعال داشته باشد.
3. **تخصیص صفر در حلقه رندر:** هیچ تابعی در تسک گرافیک نباید از `malloc` یا بازسازی داینامیک آبجکت استفاده کند.

### ماژول ۷: سیستم چندزبانه بدون نشت و فونت بدون توفو (Trilingual Zero-Tofu)

#### صورت چالش:
تبدیل حروف ترکی به کاراکترهای مربعی `[]` و وارونه شدن اعداد در کنار متن فارسی به علت باگ الگوریتم یونیکد BiDi.

#### قوانین الزامی:
1. **عاری از اکسنت در ترکی استانبولی:** در لغت‌نامه فونت یکان فارسی، از نگارش بدون اکسنت اسکی برای زبان ترکی استفاده شود (`Turkce`, `Sifirla`, `Kasnak`, `Bicak`, `Kelepce`, `Baslat`, `Durdur`).
2. **ایزولاسیون مقادیر عددی BiDi:** هرگز مقادیر عددی را مستقیماً کنار علامت دونقطه قرار ندهید. مقادیر عددی و واحدها باید درون کانتینر ایزوله با جهت `LV_BASE_DIR_LTR` قرار گیرند یا برای زمان‌ها از متون گسسته فارسی استفاده شود (`یک ربع`, `نیم ساعت`, `۱ ساعت`).
3. **تراز ریاضی ارقام:** کادر مقدار باید پدینگ صفر داشته و رقم با `lv_obj_center` در مرکز قفل شود تا از سقوط ارقام جلوگیری گردد.
4. **مرز تراز هندسی ۴۰۶ پیکسل:** لبه سمت راست کارت‌ها و نوارهای مجاور منوی زبانه‌ها باید دقیقاً روی خط فرضی `x=406` بنشیند و از خطوط حاشیه بیرون نزند.

### ماژول ۸: اصول ایمنی سخت‌افزار، منطق رله‌ها و دیبانس سنسورها (Safety Rigor)

#### قوانین تخطی‌ناپذیر سخت‌افزاری:
1. **پولاریته رله‌های خروجی (Active-LOW):** تمامی خروجی‌های ۲۴ ولت و شیرهای برقی با منطق ۰ فعال و با سطح ۱ قطع می‌شوند. در تابع بوت `outputs_init()`، باید ابتدا سطح پین‌ها روی ۱ تنظیم شود، سپس پین به عنوان خروجی پیکربندی گردد تا از پرش و تحریک ناخواسته رله‌ها در زمان استارت جلوگیری شود.
2. **قطع آنی توقف اضطراری (E-Stop):** کلید قارچی استپ پنل باید با اولویت بالا پایش شده و ظرف کمتر از ۲۰ میلی‌ثانیه تمامی خروجی‌ها و شیرهای پنیوماتیک را به حالت امن ببرد.
3. **تایم‌اوت‌های صلب جک‌ها و تیغه‌ها:** هیچ حرکتی بدون سقف زمانی مجاز نیست. عدم دریافت فیدبک میکروسوئیچ در بازه زمانی معین، باید بلافاصله منجر به آلارم خطای تایم‌اوت و توقف فرآیند شود.

### ماژول ۹: جعبه‌ابزار تست آفلاین، بیلد و استاندارد استقرار سرور

#### قوانین بیلد و انتشار:
1. **ممنوعیت مطلق فلش فیزیکی بدون اجازه صریح:** ایجنت‌ها حق اجرای دستورات آپلود مستقیم روی پورت COM فیزیکی بدون کلمه صریح «فلش کن» را ندارند.
2. **سوئیت اعتبارسنجی آفلاین پایتون:** هر پروژه باید اسکریپت تست آفلاین فریمور داشته باشد تا امضای باینری `0xE9`، جدول پارتیشن و سمبل‌های لینکر را پیش از ارائه بررسی کند.
3. **پکیج دسکتاپ ۲ فایله سرور:**
   - منحصراً دو فایل روی دسکتاپ: `firmware.bin` و `lastfile`.
   - ساختار ۸ بخشی دقیق `lastfile` بدون پین بازر و همراه با پایه‌های کمکی `M0..M7`.
   - لاگ تجمعی (Rollup Changelog) جهت نمایش تغییرات برای ارتقای مستقیم اپراتور.

### ماژول ۱۰: ایمنی قطعی لحظه صفر روشن شدن کنترلر (Boot Failsafe & Zero-Glitch Output Clamping)

#### صورت چالش:
در لحظه اتصال برق (Power-On) یا ریست ناشی از نوسان، پین‌های خروجی تا بارگذاری درایورها حالت شناور گرفته و موجب جهش‌های ناخواسته چند ده میلی‌ثانیه‌ای (Relay Chatter) می‌شوند که در اره‌ها، المنت‌های جوش و کمپرسورها خطرساز است.

#### الگوی استاندارد هافلر:
1. **پیش‌تنظیم صلب سطح پایه‌ها قبل از پیکربندی:**
   ```c
   /* ابتدا سطح خروجی‌ها را روی حالت غیرفعال قفل کنید */
   gpio_set_level(RELAY_1, 1); /* Active-LOW: 1 = OFF */
   gpio_set_level(RELAY_2, 1);
   gpio_set_level(BUZZER_PIN, 0); /* 0 = Silent */
   ```
2. **استفاده از مود `GPIO_MODE_INPUT_OUTPUT` با مقاومت Pull-Up داخلی:**
   پین‌ها را به صورت دوطرفه با پول‌آپ سخت‌افزاری فعال کنید تا هم گلیچ صفر شود و هم امکان خواندن وضعیت واقعی پایه میسر باشد.
3. **فراخوانی در خط اول `app_main()`:**
   تابع `outputs_init()` باید نخستین خط کدی باشد که پیش از NVS، صف‌ها، تسک‌ها یا ال‌سی‌دی اجرا می‌شود.

### ماژول ۱۱: سیستم قفل اقساط چندمرحله‌ای با تقویم شمسی جلالی (5-Stage Cascading Day-Lock & Jalali Leases)

#### صورت چالش:
فروش اقساطی ماشین‌آلات نیازمند زنجیره‌ای از تایمرهای متوالی و مستقل است و نمایش صرفاً تعداد روزها برای اپراتور کارگاهی مبهم است. تکنسین باید تاریخ دقیق سررسید تقویمی هر قسط را به صورت شمسی (جلالی) مشاهده کند.

#### الگوی استاندارد هافلر:
1. **محاسبه تجمعی تاریخ‌های شمسی:**
   سررسید قسط $n$-ام برابر است با تاریخ امروز به اضافه مجموع روزهای اقساط ۱ تا $n$. با الگوریتم محاسباتی سبک بدون کتابخانه (`gregorian_to_jalali`)، تاریخ دقیق تقویمی شمسی موعد هر قسط محاسبه و نمایش داده می‌شود.
2. **مکانیزم چالش-پاسخ ۴ رقمی سریع:**
   تولید کد چالش ۴ رقمی تصادفی (۱۰۰۰ تا ۹۹۹۹) هنگام انقضای قسط، و تولید پاسخ با فرمول قطعی مدیر:
   $$r_i = ((d_i \times 3) + (i + 1)) \pmod{10} \quad (i = 0..3)$$
3. **کلیدهای آزادسازی مستر و ادمین (`1234`):**
   با ورود پین ادمین، کلیه ۵ تایمر به صورت یکپارچه غیرفعال و دستگاه آزاد می‌شود.

### ماژول ۱۲: معماری عیب‌یابی و دیاگ قطعی سخت‌افزار (Definitive Real-time I/O Diagnostics)

#### صورت چالش:
در مد دیاگ (F6)، خواندن سطح پایه با `gpio_get_level()` روی پین‌های تعریف‌شده به عنوان خروجی صرف، مقدار معتبر برنمی‌گرداند و رله‌ها تاگل نمی‌شوند. همچنین تاخیر در نمایش سنسورها کارایی تست را از بین می‌برد.

#### الگوی استاندارد هافلر:
1. **ماسک نرم‌افزاری وضعیت رله‌ها:**
   کنترل تاگل رله‌ها با متغیر بیتی `s_relay_state_mask` انجام شده و خروجی با فیدبک بصری سبز درخشان (`#16a34a`) در حالت وصل و تیره در حالت قطع هدایت می‌شود.
2. **اینترلاک ایمنی فرآیند جاری:**
   در حین اجرای هر سیکل کاری اتوماتیک یا شستشو، دستکاری دستی رله‌ها در دیاگ باید مسدود شود.
3. **لامپ‌های سیگنال ورودی ۱۴px با رفرش Dirty-Driven:**
   لامپ‌های سنسورها با قطر حداقل ۱۴ پیکسل و بوردر ۲px طراحی شده و با رویکرد Dirty-Driven در چرخه ۵۰ms با سبز نئونی (`#22c55e`) روشن می‌شوند.

### ماژول ۱۳: ارگونومی استپرها و فاصله تنفس اپل (Stepper Ergo & 16px Breathing Room)

#### صورت چالش:
در کارت‌های استپر افقی، فشرده‌سازی عناصر موجب چسبیدن دکمه `+` به متن عناوین و خطای بصری در زبان‌های راست‌به‌چپ (RTL) می‌شود.

#### قوانین الزامی:
1. **مارجین امن حداقل ۱۶ پیکسل:**
   فاصله میان انتهای کنترل‌های عددی (`ctrl_end_x`) و شروع متن عنوان باید حداقل ۱۶ پیکسل باشد (`lbl_x = ctrl_end_x + 16`).
2. **مهار عرض متن در RTL:**
   در فارسی، متن با `LV_ALIGN_RIGHT_MID, -8, 0` قفل شده و عرض حداکثر آن (`max_title_w = w - lbl_x - 8`) محدود می‌گردد تا هرگز به دکمه `+` نرسد.
3. **تراز ریاضی ارقام در مرکز کادر:**
   کادر نمایش عدد با پدینگ صفر (`pad_all = 0`) ایجاد شده و متن با `lv_obj_center()` در مرکز هندسی تراز می‌شود تا از سقوط بصری جلوگیری گردد.
4. **حذف اختصارات گنگ:**
   استفاده از نگارش کامل واحدها («(ثانیه)»، «(میلی‌ثانیه)»، «(یک‌دهم آمپر)») جهت پیشگیری از وارونگی BiDi و خوانایی حداکثری.

### ماژول ۱۴: طراحی کی‌پد صنعتی، کلید چشم و پنجره‌های راهنما (Apple HIG Keypad & Modals)

#### صورت چالش:
پاپ‌آپ‌های رمز و راهنما در محیط‌های کارگاهی در صورت عدم تعبیه دکمه چشم برای دیدن ارقام، بریدگی خطوط پیام خطا، یا هم‌پوشانی دکمه بستن با متن، اپراتور را دچار سردرگمی می‌کنند.

#### قوانین الزامی:
1. **دکمه چشم (Eye Toggle):**
   تعبیه کلید لمسی در کنار کادر رمز با نمادهای `LV_SYMBOL_EYE_OPEN` و `LV_SYMBOL_EYE_CLOSE` جهت سوئیچ آزاد میان حالت گلوله‌ای (`* * * *`) و ارقام آشکار.
2. **رنگ‌آمیزی معنایی کلیدهای ماتریس کی‌پد:**
   کلید تایید (OK/Enter) به رنگ سبز زمردی (`#16a34a`) و کلید پاک‌کردن (DEL/Backspace) به رنگ قرمز صنعتی (`#dc2626`) با استفاده از رویکرد `LV_EVENT_DRAW_TASK_ADDED`.
3. **محدودسازی طول رشته در لایه لاجیک:**
   قفل طول پین به حداکثر مجاز (مثلاً ۴ رقم) جهت جلوگیری از سرریز بافر.
4. **چیدمان عمودی لایه‌بندی‌شده پنجره‌های پاپ‌آپ:**
   هدر در بالا (`y=4`)، متن راهنما در مرکز با ارتفاع معین، و دکمه بستن در پایین بدون استفاده از ترازهای درصدی شناور که منجر به هم‌پوشانی می‌شوند.

### ماژول ۱۵: ایزولاسیون نردبان مقاومتی آنالوگ و پیشگیری از پرش فانتوم کلیدها (Floating ADC Ladder Isolation)

#### صورت چالش:
در بردهای جدید که تمام ورودی‌ها دیجیتال مستقیم Active-LOW با مقاومت Pull-Up داخلی هستند، پین‌های آنالوگی که قبلاً برای نردبان‌های مقاومتی کی‌پد استفاده می‌شدند در هوا شناور می‌مانند. ولتاژ نویز القایی این پین‌ها را به سقف ۴۰۹۵ رسانده و روال‌های ADC شرط فشردن کلید را فعال ارزیابی کرده و باعث پرش‌های مکرر و غیرقابل پیش‌بینی صفحه و باز شدن منوها در کارگاه می‌شوند.

#### قوانین الزامی:
1. **قفل صلب ماکروی سخت‌افزاری:**
   در تمام پروژه‌های مبتنی بر برد ETV3A دیجیتال، ماکروی نردبان مقاومتی صریحاً صفر شود:
   ```c
   #define KEYPAD_ADC_RESISTOR_LADDER 0
   ```
2. **بایپس کامل توابع ADC کی‌پد:**
   در لایه اکشن و کلیدها، تابع خواندن آنالوگ منحصراً در صورت فعال بودن ماکرو کدگذاری شود تا هیچ چرخه‌ای از CPU برای قرائت مقادیر نویز تلف نشود:
   ```c
   #if KEYPAD_ADC_RESISTOR_LADDER
   uint16_t raw_adc = adc1_get_raw(ADC1_CHANNEL_X);
   ...
   #endif
   ```

### ماژول ۱۶: مصونیت کامل پورت سریال پایتون از ریست خودکار برد (PySerial DTR/RTS Auto-Reset Immunity)

#### صورت چالش:
کنترلرهای ESP32 دارای مدار دانلود خودکار دو ترانزیستوری هستند که به خطوط DTR و RTS پورت سریال متصل است. کتابخانه `serial.Serial` در پایتون به محض باز کردن پورت به صورت پیش‌فرض این خطوط را فعال کرده و پین EN میکرو را به زمین متصل می‌کند. این امر موجب ریست ناخواسته دستگاه و خروج از چرخه کاری حین اجرای اسکریپت‌های تست، مانیتورینگ یا عکس‌برداری سریع RAWSHOT می‌شود.

#### قوانین الزامی:
1. **غیرفعال‌سازی صلب DTR و RTS قبل و بعد از باز شدن پورت:**
   در تمام ابزارهای تست پایتون بدون استثنا:
   ```python
   ser = serial.Serial()
   ser.port = port
   ser.baudrate = baudrate
   ser.timeout = timeout
   ser.dtr = False
   ser.rts = False
   ser.open()
   ser.dtr = False
   ser.rts = False
   ```

### ماژول ۱۷: تست خودکار نرم‌افزاری HIL بدون سنسور و موتور فیزیکی (Headless Hardware-in-the-Loop)

#### صورت چالش:
توسعه‌دهنده در محیط اداری به موتورها، جک‌ها، ترموکوپل‌ها یا خط‌کش‌های میلی‌متری واقعی وصل نیست و نمی‌تواند رفتار ماشین را در شرایط کارگاهی بیازماید.

#### قوانین الزامی:
1. **تزریق ورودی‌های شبیه‌سازی‌شده از طریق سریال یا متغیرهای تست:**
   تعبیه فلگ‌های تست بدون نشت به نسخه ریلیز، جهت ارسال لبه‌های مجازی پالس پولی، سوئیچ‌های کلمپ، یا مقادیر ترموکوپل.
2. **تست تعاملی کلیدها و ضبط فریم:**
   شبیه‌سازی رویدادهای لمسی یا فشردن کلیدها و دریافت فریم‌بافر با سرعت ۹۲۱,۶۰۰ باود جهت تایید ۱۰۰٪ رفتار ماشین وضعیت FSM پیش از ورود به فاز تولید.

### ماژول ۱۸: قانون طلایی ممانعت از وارونگی BiDi و ارقام زمان‌سنج‌ها (The BiDi Anti-Inversion & Number Safety Rule)

#### صورت چالش:
در متون راست‌به‌چپ (فارسی)، کاراکتر دونقطه (`:`) به عنوان کاراکتر خنثی در موتور LVGL ارزیابی شده و باعث معکوس شدن ارقام قبل و بعد آن می‌شود (مثلاً فرمت `%02d:%02d` زمان `02:59` را به `59:02` معکوس می‌کند و جای دقیقه و ثانیه عوض می‌شود). این عیب در تمام ۱۱ ماشین (تایمر جوش، زمان برش، زمان پخت، زمان تزریق گاز، استراحت کمپرسور) می‌تواند موجب اشتباه اپراتور گردد.

#### قوانین الزامی:
1. **ممنوعیت مطلق دونقطه برهنه در متن RTL:** هرگز از `%02d:%02d` در رشته‌های فارسی استفاده نکنید.
2. **الزام به قالب فارسی طبیعی:**
   - اگر دقیقه بزرگ‌تر از صفر باشد: `"%s: %d دقیقه و %02d ثانیه"`
   - اگر دقیقه صفر باشد: `"%s: %d ثانیه"`
3. **قفل صریح LRO برای لاتین و ترکی:** در متون انگلیسی و ترکی، رشته باید درون کاراکترهای یونیکد ایزولاسیون چپ‌به‌راست محصور شود:
   `"\xE2\x80\xAD%02d:%02d\xE2\x80\xAC"`

### ماژول ۱۹: پایشگر ارتفاع و بریدگی خط کرسی دیالوگ‌ها (Viewport Baseline Clipping Guard)

#### صورت چالش:
در دیالوگ‌های خطا، پاپ‌آپ‌ها و کادرهای اطلاعاتی، اگر ارتفاع مفید کانتینر کمتر از مجموع ارتفاع خطوط متن باشد یا اسکرول‌بار فعال شود، حروف خط آخر روی خط کرسی بریده شده و کلماتی مانند «از» به حروف شکسته نامفهوم تبدیل می‌شوند.

#### قوانین الزامی:
1. **بافر ارتفاع عمودی (+۲۰px):** ارتفاع کانتینر دیالوگ باید همیشه حداقل ۲۰ پیکسل فراتر از محتوای متنی باشد تا خط پایانی بدون اسکرول کامل دیده شود.
2. **پدینگ فشرده داخلی:** پدینگ سطری `pad_row` به ۳ تا ۴ پیکسل و پدینگ داخلی `pad_all` به ۶ تا ۸ پیکسل تنظیم شود.
3. **کاهش ارتفاع هدر:** ارتفاع هدر مودال‌ها حداکثر ۳۶ پیکسل باشد تا فضای عمودی مفید بدنه متن آزاد گردد.

### ماژول ۲۰: ایمنی کران‌های استپر و تطابق مقادیر پیش‌فرض NVS (Stepper Clamp Bounds Invariant)

#### صورت چالش:
پارامترهایی که به صورت پیش‌فرض در NVS مقادیر بزرگ دارند (مانند دوره استراحت ۷۲۰۰ ثانیه‌ای کمپرسور، یا طول پروفیل ۳۰۰۰ میلی‌متری در اره برش)، در صورتی که کران بالای استپر HMI به اشتباه روی ۹۹۹ محدود شده باشد، با اولین لمس کلید `+` یا `-` ناگهان به ۹۹۹ سقوط کرده و پارامتر ماشین مخدوش می‌شود.

#### قوانین الزامی:
1. **انطباق صلب کران بالا با بزرگ‌ترین مقدار مهندسی:** استپرهای زمانی تا ۸۶۴۰۰ ثانیه (۲۴ ساعت) و استپرهای طول تا ۶۰۰۰ میلی‌متر باز باشند.
2. **بررسی استاتیک خودکار:** در سوئیت‌های تست آفلاین، بازه مجاز تمام استپرها در برابر مقادیر پیش‌فرض کد C اعتبارسنجی شوند.

---

### ماژول ۲۱: یکپارچگی صلب وب‌پورتال با نمایشگر فیزیکی (WebPortal-HMI Synchronization Rigor)

#### صورت چالش:
ناهمخوانی میان واحدهای اندازه‌گیری، اسامی پارامترها و کران‌های مجاز در وب‌پورتال موبایل و صفحه نمایش HMI موجب خطای اپراتور و سردرگمی مشتری در کارگاه می‌شود (مانند نمایش ثانیه در وب و دقیقه در HMI).

#### قوانین الزامی:
1. **منبع واحد متغیرها:** نام پارامترها، واحدها (دقیقه، ثانیه، درجه سانتی‌گراد، میلی‌متر) و فرمول‌های تبدیل در کد سرور وب (`webportal.c`) دقیقاً با فایل مرجع `project_config.h` و صفحه HMI یکسان باشند.
2. **پوشش کامل لغت‌نامه وب:** در تمام ۳ زبان، برچسب‌های وب‌پورتال فاقد کلمات ترجمه‌نشده یا زبان پیش‌فرض نشت‌کرده باشند.

### ماژول ۲۲: چارچوب جامع آزمون پذیرش کارگاهی و تحویل به مشتری (The FAT/SAT Master Acceptance Testing Framework)

#### قوانین الزامی تحویل برای کلیه ۱۱ ماشین:
هر پروژه پیش از تحویل فیزیکی به مشتری باید نقشه آزمون ۶ فازه اختصاصی داشته باشد:
1. **فاز ۱: بوت سرد و سلامت بصری (Cold Boot & Optical Polish):** بررسی سلامت ال‌سی‌دی، ساعت RTC، تراز هندسی و لوگو.
2. **فاز ۲: آزمون مدهای عملکردی (Functional Operations):** تست توالی خودکار، مدهای دستی، تایمرهای بدون وارونگی.
3. **فاز ۳: آزمون فیدبک سنسورها (Sensor Interlocks):** بررسی میکروسوئیچ‌ها، پالس‌های انکودر، پراب‌های دما.
4. **فاز ۴: آزمون استپ اضطراری و ریست (E-Stop & Fault Recovery):** قطع زیر ۲۰ms رله‌ها و پالس ریست مدار فرمان.
5. **فاز ۵: آزمون سیستم اقساط و امنیت (Day-Lock Leasing):** بررسی اعتبار روزها و زنجیره ۵ قسط.
6. **فاز ۶: چک‌لیست تحویل نهایی (Final Handover):** اتصال پراب‌ها، صفر کردن شمارنده‌های تستی و سوئیچ سه‌زبانه.

| **پلتفرم تست کانفیگ** | ESP32-S3 | ماتریس ورودی‌های تست I0..I7 | رله‌های تستی Q0..Q8، بازر، SSR | عیب‌یابی برد، تست تاچ و کالیبراسیون | دیاگ سخت‌افزاری بلادرنگ با فیدبک بصری LED |

## ۴. جمع‌بندی و گیت‌های کنترل کیفی (Quality Gates)

هر ایجنتی که بر روی هر یک از پروژه‌های بالا فعالیت می‌کند، پیش از پایان تسک باید از تطابق کد با ۱۷ ماژول فوق اطمینان حاصل کرده و گزارشی خلاصه و تلگرافی همراه با درصد پیشرفت به کاربر ارائه دهد.
