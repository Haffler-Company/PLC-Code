# راهنمای جامع تاب‌آوری در برابر کرش، ثبت خطا و بازیابی خودکار فریمور
## راهنمای تخصصی ESP32-S3: ثبت وقایع در RTC، صفحه ریکاوری اپراتور، رول‌بک هوشمند OTA و کنترل افت ولتاژ

> **هدف:** حذف کامل پدیده «دستگاه بی‌دلیل ریست شد و کسی نفهمید چرا». دستگاه صنعتی در صورت بروز هرگونه ریست سخت‌افزاری، افت ولتاژ (Brownout) یا تریپ واچ‌داگ، باید علت دقیق را در حافظه ماندگار ثبت کند، خروجی‌ها را در امن‌ترین حالت نگه دارد و صفحه بازیابی به اپراتور ارائه دهد. همچنین در صورت آپدیت فریمور معیوب، سیستم به صورت کاملاً خودکار به نسخه سالم قبلی بازگردد (Rollback).

---

## ۱. دسته‌بندی و رهگیری دلایل ریست سیستم (Reset Reason Inspection)

در ابتدای تابع `setup()` یا قبل از راه‌اندازی تسک‌های کنترلی، علت ریست پردازنده باید استخراج و لاگ شود:

```c
#include "esp_system.h"

typedef struct {
    esp_reset_reason_t reason;
    uint32_t crash_timestamp;
    uint32_t program_counter_pc;
    char fault_description[64];
} crash_diagnostic_record_t;

// متغیری که در حافظه رم بدون پاک‌شدن در ریست باقی می‌ماند:
RTC_NOINIT_ATTR crash_diagnostic_record_t g_rtc_crash_record;

void inspect_and_log_reset_reason(void) {
    esp_reset_reason_t reason = esp_reset_reason();
    
    switch (reason) {
        case ESP_RST_POWERON:
            // استارت نرمال و روشن شدن برق دستگاه
            break;
            
        case ESP_RST_BROWNOUT:
            // افت ولتاژ برق ورودی به دلیل کشش جریان کنتاکتور یا خرابی پاور
            log_critical_event(0x00B1, "ریست افت ولتاژ برق ورودی (Brownout)");
            break;
            
        case ESP_RST_TASK_WDT:
            // قفل شدن یکی از تسک‌های بلادرنگ و تریپ واچ‌داگ
            log_critical_event(0x00E2, "تریپ واچ‌داگ نرم‌افزاری (Task WDT)");
            break;
            
        case ESP_RST_PANIC:
            // کرش ناشی از خطای حافظه (Null Pointer, LoadProhibited)
            log_critical_event(0x00EE, "کرش هسته پردازنده (Core Panic)");
            break;
            
        default:
            break;
    }
}
```

## ۲. صفحه بازیابی پس از کرش در HMI (Crash Recovery Screen)

اگر دستگاه به دلیل `PANIC`، `TASK_WDT` یا `BROWNOUT` ریست شود، **نباید** مستقیماً وارد صفحه کار عادی شود و آماده استارت باشد! این یک خطر فیزیکی است. در عوض، یک صفحه اختصاصی هشدار قرمز به سبک اپل نمایش داده می‌شود:

```
+-------------------------------------------------------------+
| [!] هشدار سیستمی: راه‌اندازی مجدد پس از وقفه اضطراری         |
+-------------------------------------------------------------+
| علت رخداد: قفل موقت زمان‌بندی تسک (Task WDT Timeout)        |
| زمان وقوع: 14:28:15  |  کد خطا: 0x00E2                      |
|                                                             |
| کلیه خروجی‌ها و جک‌ها در وضعیت ایمن (غیرفعال) قفل شده‌اند. |
| لطفاً وضعیت مکانیکی قطعات و فشار باد را بررسی فرمایید.     |
|                                                             |
|               [ تأیید اپراتور و شروع مجدد ]                 |
+-------------------------------------------------------------+
```

### الزامات صفحه بازیابی:
1. تا زمانی که اپراتور دکمه تایید را لمس نکند، ماشین اجازه اجرای سیکل خودکار را نخواهد داشت.
2. کلیه متغیرهای موقعیت به حالت نیازمند هومینگ (`Needs Homing`) می‌روند تا موقعیت اره یا جک‌ها دوباره کالیبره شود.

## ۳. معماری آپدیت مطمئن و بازگشت خودکار فریمور (Automatic OTA Rollback)

در پارتیشن‌بندی دوگانه ESP32 (`ota_0` و `ota_1`)، اگر فریمور جدیدی از طریق وای‌فای یا فایل آپلود شود، سیستم باید دارای مکانیزم ایمنی ۶۰ ثانیه‌ای باشد:

```c
#include "esp_ota_ops.h"

void verify_firmware_health_and_confirm(void) {
    const esp_partition_t *running = esp_ota_get_running_partition();
    esp_ota_img_states_t ota_state;
    
    if (esp_ota_get_state_partition(running, &ota_state) == ESP_OK) {
        if (ota_state == ESP_OTA_IMG_PENDING_VERIFY) {
            // این فریمور تازه آپدیت شده و در دوره آزمایشی است
            // بررسی سلامت سیستم: تاچ سالم است؟ ارتباط با سنسورها برقرار است؟
            if (system_health_self_test_passed()) {
                // تایید فریمور جدید به عنوان نسخه دائمی:
                esp_ota_mark_app_valid_cancel_rollback();
            } else {
                // تست ناموفق بود! بازگشت فوری به نسخه قبل بدون دخالت انسان:
                esp_ota_mark_app_invalid_rollback_and_reboot();
            }
        }
    }
}
```

> **قانون رول‌بک:** اگر فریمور جدید بعد از بوت دچار کرش یا ریست متوالی شود، بوت‌لودر ESP32 به صورت خودکار نسخه قبلی سالم را لود می‌کند و مانع از بریک‌شدن برد در کارگاه می‌شود.

## ۴. پیکربندی تشخیص افت ولتاژ (Brownout Detector Configuration)

شیرهای پنوماتیک بزرگ و کنتاکتورهای ۲۲۰ ولت هنگام وصل، افت ولتاژ ناگهانی در منبع تغذیه ۲۴V ایجاد می‌کنند که از طریق رگولاتور به ریل ۳.۳ ولت میکروکنترلر سرایت می‌کند.

1. تنظیم آستانه براون‌اوت در `sdkconfig`:
   ```text
   CONFIG_ESP_BROWNOUT_DET=y
   CONFIG_ESP_BROWNOUT_DET_LVL_SEL_7=y ; آستانه حدود ۲.۸ ولت
   ```
2. استفاده از خازن‌های الکترولیتی و تانتالیومی کم‌مقاومت (Low-ESR) با ظرفیت حداقل ۱۰۰۰ میکروفاراد در ورودی رگولاتور ۳.۳V برد HMI.
3. در صورت افت ولتاژ، لاجیک باید ذخیره فوری مقادیر بحرانی شیفت در حافظه RTC Fast Memory را طی ۲ میلی‌ثانیه قبل از خاموشی کامل انجام دهد.
