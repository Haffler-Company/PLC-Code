# قوانین عمومی مخزن PLC

این فایل قواعد مشترک نگهداری مخزن را مشخص می‌کند تا همه پروژه‌ها برای GitHub، توسعه تیمی، تولید و خدمات قابل پیگیری باشند.

## قواعد نام‌گذاری

- نام پروژه‌ها در سطح اول باید ثابت بماند: `PLC 5K`، `PLC 8K`، `PLC 10K`، `PLC HMI`.
- نسخه‌ها بهتر است با قالب یکسان نوشته شوند: `V.x.y.z`.
- برای فایل‌های جدید از نام انگلیسی بدون غلط املایی استفاده شود؛ نمونه اصلاحی: `Program Address.txt`.
- پوشه‌های کد بهتر است لاتین و بدون فاصله باشند. برای مستندات فارسی، نام فارسی قابل قبول است.
- فایل‌های upstream کتابخانه‌ها فقط در صورت نیاز واقعی تغییر کنند و تغییراتشان در README همان پروژه توضیح داده شود.

## قواعد ساختار

- هر پروژه باید `README-PLC-*.md` داشته باشد.
- هر پروژه باید در `Docs/KNOWLEDGE.md` دانش فنی خود را ثبت کند.
- هر نسخه نرم‌افزاری باید README یا یادداشت release شامل هدف نسخه، برد هدف، روش build و روش flash داشته باشد.
- هر تغییر سخت‌افزار باید همراه با BOM و خروجی قابل مشاهده برای افراد بدون Altium باشد، مثل PDF یا HTML.

## قواعد GitHub

- پوشه‌های `.git` داخلی نباید داخل مخزن اصلی باقی بمانند مگر اینکه عمداً submodule تعریف شده باشند.
- خروجی‌های build، cache، `.pio`، فایل‌های موقت Altium و فایل‌های سیستم‌عامل نباید commit شوند.
- فایل‌های حجیم فقط وقتی در مخزن بمانند که برای ساخت، تولید یا مستندسازی ضروری باشند.
- برای مخزن public، رمزهای پیش‌فرض، tokenها، SSID/password واقعی و کدهای اضطراری باید حذف یا نمونه‌سازی شوند.

## قواعد ثبت تغییرات

- هر اصلاح ساختاری یا مستنداتی در `FIXES.md` ثبت شود.
- موارد انجام‌شده، موارد باقی‌مانده، تصمیم‌های مالک پروژه و ریسک‌های انتشار جدا نوشته شوند.
- اگر کد تغییر کند، نسخه نرم‌افزار یا توضیح release باید به‌روزرسانی شود.

## قواعد همکاری

- تغییرات سخت‌افزار فقط توسط مسئول سخت‌افزار یا با تایید او انجام شود.
- تغییرات نرم‌افزار فقط در پوشه نسخه/پروژه مربوطه انجام شود.
- قبل از push، وضعیت `git status` بررسی شود و حذف/افزودن فایل‌ها آگاهانه باشد.
- برای هر محصول، یک نفر مالک مستندات تعیین شود تا README و KNOWLEDGE همیشه با وضعیت واقعی پروژه هماهنگ بماند.
